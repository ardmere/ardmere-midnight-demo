# Merkle Sum Tree (MST) encoding — three-asset signed balances

Fixed batch size **`LEAF_COUNT = 64`** (full binary tree, depth **6**). The
MVP tracks three assets: **BTC**, **ETH**, **USDT**.

## Units

| Asset | Smallest unit | Decimals |
| --- | --- | --- |
| BTC | satoshi | 8 |
| ETH | 1e-8 ETH (10 gwei) | 8 |
| USDT | 1e-6 USDT | 6 |

Leaf balances are **signed**: a user may be long BTC and short ETH at the same
time. Each signed balance `x` is encoded canonically as a pair of non-negative
magnitudes `(pos, neg)` with `x = pos - neg` and at most one side non-zero.
The circuit enforces `pos == 0 || neg == 0`.

## Leaf node

```text
LeafPreimage = {
  domain:     pad32("ardmere:mst:leaf:v3"),
  userIdHash: Bytes<32>,
  btcPos, btcNeg, ethPos, ethNeg, usdtPos, usdtNeg: Uint<64>
}
leafHash = persistentHash(LeafPreimage)
```

Leaf sums are the six `(pos, neg)` magnitudes themselves.

## Parent node

```text
ParentPreimage = {
  domain: pad32("ardmere:mst:parent:v3"),
  leftHash, rightHash: Bytes<32>,
  btcPosSum, btcNegSum, ethPosSum, ethNegSum, usdtPosSum, usdtNegSum: Uint<128>
}
```

Parent sums are component-wise additions of the child sums. Aggregates use
`Uint<128>` because 64 leaves x `Uint<64>` does not fit in 64 bits.

## Root

After 6 levels the root is `(hash, btcPosSum, btcNegSum, ethPosSum,
ethNegSum, usdtPosSum, usdtNegSum)`. Net exposure per asset is
`posSum - negSum` (may be negative).

## Per-user NAV

Prices are **public circuit inputs**, expressed in micro-USDT per smallest
asset unit (demo: BTC 600, ETH 30, USDT 1, i.e. 60k/3k/1 USDT):

```text
posValue = btcPos*priceBtc + ethPos*priceEth + usdtPos*priceUsdt
negValue = btcNeg*priceBtc + ethNeg*priceEth + usdtNeg*priceUsdt
NAV      = posValue - negValue          // micro-USDT
assert NAV > 0
```

Each leaf is checked (unrolled 64 times). Prices are bounded
(`0 < price <= 1e12`) so `Uint<128>` arithmetic cannot overflow.

## Solvency check

For each asset:

```text
netExposure = posSum - negSum
assert posSum <= negSum + declaredReserves
```

i.e. net exposure must not exceed the operator's declared reserves. Negative
net exposure trivially passes.

## Inclusion path

Sibling nodes carry their six gross sums. A verifier recomputes every parent
sum and hash from the user's signed balances plus 6 sibling nodes, and checks:

- leaf hash matches `(userIdHash, btc, eth, usdt)`;
- recomputed root equals the published root;
- recomputed net liabilities equal the declared snapshot liabilities;
- the user's NAV at the published prices is positive.

## Circuit alignment

`contract/mst_hash.compact` exports `leafHash`, `parentHash`, `signedValid`
and `navPositive`. `contract/mst_root_unrolled.compact` is generated by
`scripts/generate-mst-unrolled.compact.ts` and contains the 63 combines plus
the 256 unrolled signed/NAV checks. TypeScript in `src/mst/` must match the
compiled `pureCircuits` (see `test/mst.test.ts`).

## Out of scope

- Real-time / oracle prices — prices are operator-supplied public inputs.
- Multi-batch aggregation, 1024+ leaves, cross-asset netting beyond NAV.
- Proving that `declaredReserves` corresponds to real assets.
